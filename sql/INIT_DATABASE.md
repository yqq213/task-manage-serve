# 一键初始化数据库

`init_task_manage.sql` 是独立的完整脚本，不需要先执行其他 SQL 文件。
适用于 MySQL 8.0.16 及以上版本，固定创建并使用 `task-manage` 数据库，字符集为 `utf8mb4`。

## 执行

在仓库根目录运行，按提示输入 **MySQL 数据库管理员密码**：

```sh
mysql --host=39.96.7.19 --port=3306 --user=root --password --ssl-mode=REQUIRED --default-character-set=utf8mb4 < sql/init_task_manage.sql
```

这里的 MySQL 登录账号与下面的应用管理员账号是两种不同账号。
执行账号需有建库、建表、创建和执行存储过程及写入数据的权限。
脚本使用 `DELIMITER`，上面的 MySQL 命令行支持此语法；不能用普通 JDBC 单条 SQL 执行器直接执行整个文件。

初始化成功后返回“初始化完成”、管理员用户名和表数量 `33`。
后端数据库配置须指向 `task-manage`，然后启动后端及前端即可登录。

## 初始应用管理员

| 项目 | 值 |
| --- | -- |
| 用户名 | `admin` |
| 初始密码 | `admin123` |
| 昵称 | 系统管理员 |
| 用户 ID | `1` |
| 角色 | 超级管理员 |

密码使用项目兼容的 BCrypt 哈希入库，首次登录后请修改密码。
只初始化一个应用用户；原基础脚本的测试用户 `ry` 及其角色、岗位关联不写入。
保留若依基础部门、岗位、角色、菜单、字典、配置和默认示例数据，建立 Quartz 调度表及任务、操作记录表；任务数据为空。
脚本不创建 MySQL 账号，也不修改服务器已有账号、权限或后端连接配置。

## 已有数据与失败处理

目标库只要存在任意表或视图，就返回 `Initialization refused`，不会删除、重建或覆盖已有表。
检查与全部初始化语句位于同一存储过程内，即使客户端使用 `--force` 继续执行也不能绕过检查。
正常执行不要添加 `--force`，便于任何错误立即停止。

MySQL DDL 隐式提交，初始化中途失败可能留下已创建的表，不能保证整体回滚。
此时应检查错误和已创建对象，保留现场；不要删除业务数据或盲目重复执行。

如果检查拒绝执行，或初始化中途失败，MySQL 客户端默认停止，可能留下辅助存储过程 `initialize_task_manage`。
确认它来自本脚本后，可以只删除该辅助过程（不删除表、不修改数据）：

```sql
DROP PROCEDURE IF EXISTS `task-manage`.`initialize_task_manage`;
```

重复初始化不是数据库升级方式；已有数据库应使用针对性的迁移脚本。
